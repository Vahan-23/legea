5. КАТАЛОГ И ДАННЫЕ
═══════════════════════════════════════════════
5.1 Источник — каталог Legea 2024. Данные gsm, sizes, colorways,
    features, tech берутся из него. Если по артикулу данных нет —
    ставь null и помечай // TODO: уточнить, НЕ выдумывай.
5.2 category: "calcio" | "volley" | "basket" | "universal".
    В universal попадают: костюмы, толстовки, куртки, брюки,
    поло, футболки, сумки, аксессуары.
5.3 Словарь type → подписи создай в messages/{locale}.json
    под ключом catalog.types.*
5.4 Костюм = ОДНА карточка. Размерная матрица одна, размеры —
    пересечение рядов куртки и брюк. В спецификации — одна позиция
    с пометкой «комплект», в PDF раскрывается на два артикула.
5.5 oversizeId / juniorId — не отдельные карточки. На карточке
    показывать бейдж «Есть oversize 3XL-4XL» / «Есть junior 3XS-XS».
    При выборе такого размера в матрице артикул в спецификации
    автоматически подменяется на B/J-версию.
5.6 Связи: M1147→M1147B, M1152→M1152B, M1166→M1166B,
    M1173→M1173B, M1143→M1143B/M1143J, M1144→M1144B/M1144J,
    M1146→M1146B/M1146J, P187→P187B, P188→P188B, P193→P193B,
    B111→B111B, PR200→PR201, G022→G022B, G027→G027B, G028→G028B.
5.7 basePrice: null. Не 0 — чтобы отличать «нет данных» от «бесплатно».
5.8 hy временно = ru. Структура готова, перевод подставляется позже.
5.9 revalidate: 3600.
5.10 Клиентская фильтрация SSG-данных. Поиск — простое включение
     подстроки по id и name, без fuzzy. Товаров меньше 100.
5.11 Пустой результат: «Ничего не найдено» + кнопка «Сбросить фильтры».
5.12 Сортировка: по артикулу (дефолт), по названию. priceLevel
     в сортировке не участвует, пока цены скрыты.
